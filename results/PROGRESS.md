## First measurement

One cell (`drift.first`: RGB888, Saira Regular @18 = ratio 1.0, `ROT_CW`, PSRAM,
async multithreaded), `-Os`, pax `964533a6d894`:

| Metric | Value |
|---|---|
| ns per iteration | 4,727,600 |
| ns per destination pixel | 349.88 |
| reps / samples | 20 / 15 |
| median / min / max | 94,552 / 94,484 / 95,000 µs |
| cv | 0.16% |
| measured CPU | 360.00 MHz |
| wall time | ~1.5 s including calibration and warm-up |

Two things worth recording:

- **Stability is far better than the harness requires.** 0.16% cv against a 3%
  limit, and a 0.55% min-to-max spread. The repeatability gate (step 8) should
  pass comfortably, though that has to be demonstrated across whole runs rather
  than inferred from one cell.
- **The measurement agrees with the static analysis.**
  `pax_font_rendering_optimization.md` §4.3 estimated ~120 instructions plus a
  divide and five calls per antialiased glyph pixel, which is ~333 ns at
  360 MHz. Measured: 349.88 ns per destination pixel, within 6%. That is one
  cell on one path, so it is corroboration rather than proof — but it is the
  first evidence that the document's instruction counts describe reality.

At ~1.5-2 s per cell, 71 cells projects to roughly 2-2.5 minutes per run, inside
the 2-5 minute target.

## Running a cycle

```bash
make bench                  # build + install + run + measure at -Os
make bench OPT=og           # the -Og control series
make benchboth              # both levels
make testbaseline           # record the current run as the reference
```

The badge must be in the launcher when a cycle starts, because `install` and
`run` both need BadgeLink. If the benchmark app is running, send it `EXIT` on
the debug console, press F1, or wait for its five-minute idle timeout.
